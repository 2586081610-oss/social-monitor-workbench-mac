# 脚标校验规则（v3）

> 适用：所有使用 v2 脚标语法产出的 80/20 笔记。脚标语法与写作要求见
> [`../v2/00-引用标记规范.md`](../v2/00-引用标记规范.md)，本文件只定义「怎么机器校验」。
> 工具：[`tools/check_footnotes.py`](tools/check_footnotes.py)，纯 Python 3 标准库，无第三方依赖。

## 一、校验目标

1. **引用与定义一一对应**：正文里出现的每个脚标都能在文末找到定义，不留悬空引用。
2. **类型合法**：脚标前缀必须是 v/s/q/d/u 之一，防止自造类型混进证据台账。
3. **证据数量可统计**：按类型统计引用次数与定义条数，给发稿前检查提供硬数字。
4. **支持/质疑平衡**：有外部证据时不能只列支持，至少要有一条质疑或「未找到」。
5. **引用密度合理**：脚标是标记，不是装饰；密度过低说明该挂没挂，过高说明在堆砌。

## 二、合法前缀

| 前缀 | 含义 | 典型用法 |
|---|---|---|
| `v` | 原片证据 | 博主原话、动作画面、板书、组数/次数 |
| `s` | 支持证据 | 论文、元分析、指南，结论与博主一致 |
| `q` | 质疑证据 | 结论与博主冲突，或只能部分支持 |
| `d` | 权威数据 | 官方统计、指南、标准、机构数据 |
| `u` | 未找到 | 查不到直接研究，明确不为该说法背书 |

编号用正整数，如 `[^v1]`、`[^s12]`。大写前缀（`[^V1]`）、多字母前缀（`[^vv1]`）、
未登记字母（`[^x1]`）一律视为非法类型。

## 三、规则列表

### 3.1 错误（error，直接判失败）

| 编号 | 规则 | 说明 |
|---|---|---|
| `E001` | 每个 `[^xN]` 必须有对应 `[^xN]:` 定义 | 同一编号多处引用只报一次，报首次出现的行号 |
| `E002` | 不允许重复定义 | 同一编号定义两次及以上即失败，提示首次定义行号 |
| `E003` | 前缀必须是 `v/s/q/d/u` | 引用和定义都检查 |
| `E004` | 必须存在「证据台账」标题 | 任意级别标题命中即可，如 `## 证据台账`、`## 九、证据台账` |
| `E005` | frontmatter 自报数量必须与实际统计一致 | 只校验写了的字段，比较基准是去重后的定义条数 |
| `E006` | frontmatter 字段值必须是整数 | 值不是整数时无法比对，直接报错 |

### 3.2 警告（warning，默认不阻塞，`--strict` 下阻塞）

| 编号 | 规则 | 说明 |
|---|---|---|
| `W001` | 不允许未使用的定义 | 定义了但正文从未引用 |
| `W002` | 有外部证据时至少 1 条 `q` 或 `u` | 只有 `s` 时报「只有支持证据」；只有 `d` 时报「只有权威数据」 |
| `W003` | 引用密度低于 0.2 个/100 中文字符 | 说明该挂脚标的可核验说法没挂 |
| `W004` | 引用密度高于 2.0 个/100 中文字符 | 说明脚标堆砌，笔记被写成文献综述 |

### 3.3 明确允许

- **同一编号多次引用**：同一来源复用一个编号是规范推荐做法，不报错，计入引用次数。
- **纯原片笔记**：只有 `v` 定义、没有任何外部证据时，不触发 `W002`（平衡规则只约束外部证据）。
- **示例代码块**：围栏代码块（```` ``` ```` / ~~~）和行内反引号代码里的脚标不参与校验，方便模板里放反例。

### 3.4 统计口径

| 指标 | 口径 |
|---|---|
| 各类型数量 | 去重后的**定义条数**（即证据台账条目数），frontmatter 也按这个口径比对 |
| 引用次数 | 正文中 `[^xN]` 的出现次数，同一编号重复引用累计 |
| 唯一编号数 | 去重后的定义编号数 |
| 中文字符数 | 去掉 frontmatter、围栏代码块、脚标定义行后，`[\u4e00-\u9fff]` 的字符数 |
| 引用密度 | `引用次数 × 100 ÷ 中文字符数`，保留 3 位小数 |
| 密度下限样本 | 中文字符不足 100 时不校验密度，`stats.density_checked` 为 `false` |

## 四、运行方式

```bash
# 人读报告
python3 docs/note-templates/v3/tools/check_footnotes.py path/to/note.md

# 机器可读（errors / warnings / stats）
python3 docs/note-templates/v3/tools/check_footnotes.py path/to/note.md --json

# 严格模式：warning 也算失败
python3 docs/note-templates/v3/tools/check_footnotes.py path/to/note.md --strict

# 内置自检（不读文件、不写文件）
python3 docs/note-templates/v3/tools/check_footnotes.py --self-test
```

### 4.1 退出码

| 退出码 | 含义 |
|---|---|
| `0` | 通过；无 error，且（未开 `--strict` 或没有 warning） |
| `1` | 存在 error；或开了 `--strict` 且存在 warning |
| `2` | 参数错误或文件读取失败（不是笔记内容问题） |

### 4.2 选项说明

- `--strict`：把 warning 升级为失败条件，适合发稿前的最后一道闸。默认只看 error。
- `--json`：输出固定结构的 JSON，字段为 `file`、`strict`、`exit_code`、`ok`、`errors`、`warnings`、`stats`。
  - `errors` / `warnings`：数组，每项含 `code`、`message`、`line`（无行号时为 `null`）。
  - `stats.by_type`：按 `v/s/q/d/u` 给出 `label`、`references`、`definitions`。
  - `stats.citation_density`：密度；未校验时为 `null`。
- `--self-test`：在内存里跑 4 个内置用例，断言退出码与关键输出：
  - 完全正确（退出码 0，无 error/warning）；
  - 引用缺定义（退出码 1，`E001`）；
  - 只有支持证据（默认 0，`--strict` 下 1，`W002`）；
  - 结构错误综合（重复定义、非法前缀、缺台账、frontmatter 不一致、未使用定义）。
  - 自检通过输出 `[自检] 通过 N 项断言（4 个用例）` 并返回 0，否则列出失败断言并返回 1。

## 五、正确示例

```markdown
---
title: 睡眠与恢复
evidence_support: 1
evidence_question: 1
evidence_data: 1
evidence_unfound: 1
---

# 睡眠与恢复

## 一句话

睡眠不足会明显拖慢训练后的恢复速度，这一点博主用自己连续两周的记录来说明[^v1]。慢呼吸能够提高迷走神经介导的心率变异性，这一点有系统综述和元分析支持[^s1]；但「四七八」这种固定比例并没有直接随机对照试验[^u1]。官方指南给成年人的建议是每晚七小时以上[^d1]。不过，把训练表现下降全部归因于睡眠并不成立，疲劳、热量缺口和训练量都需要一起看[^q1]。

## 一、具体做法

他把睡前流程拆成三步：先关掉所有强光，再做十分钟慢呼吸，最后把手机放到卧室外面。这三步里只有慢呼吸有比较明确的生理机制，其余两步属于个人经验，本条不额外引用外部研究。

## 二、边界条件

他特别强调，这套流程只在训练日执行，休息日不必照做；这个区分来自他个人的体感，而不是来自对照实验，因此只能当作经验参考，不能当成普遍适用的结论。

## 证据台账

| 编号 | 类型 | 来源 | 年份 | 支持/质疑的对象 | 强度 |
|---|---|---|---|---|---|
| v1 | 原片 | 原片 00:10 | — | 睡眠不足拖慢恢复 | — |
| s1 | 系统综述 | 某综述 | 2022 | 慢呼吸提高 HRV | 强 |
| q1 | 队列研究 | 某研究 | 2021 | 睡眠与训练表现 | 中 |
| d1 | 权威数据 | 睡眠指南 | 2020 | 成人睡眠时长 | 强 |
| u1 | 未找到 | — | — | 四七八固定比例 | — |

## 参考文献

1. 某作者. 某标题. 某期刊, 2022.

---
[^v1]: 原片 00:10，博主原话「睡不够就别练」。
[^s1]: 支持 · 慢呼吸提高 HRV。证据强度：强。
[^q1]: 质疑 · 训练表现下降受多因素影响。证据强度：中。
[^d1]: 权威数据 · 成人每晚睡眠七小时以上。
[^u1]: 未找到直接研究——本条不对固定比例做外部背书。
```

预期结果：

```text
脚标校验：note.md
[错误] 0 条
[警告] 0 条
[统计] 中文字符 402｜脚标引用 5 个（唯一定义 5 个）｜密度 1.244 / 100 字
[统计] 定义：v 1｜s 1｜q 1｜d 1｜u 1
[结果] PASS
```

## 六、错误示例

```markdown
---
evidence_support: 2
---

# 错误示例

博主建议每晚睡够七小时[^v1]，这一点有研究支持[^s1]，但另一条没有定义[^v7]。

## 证据台账

| 编号 | 类型 |
|---|---|
| v1 | 原片 |
| s1 | 支持 |

---
[^v1]: 原片 00:10。
[^s1]: 支持 · 某研究。证据强度：中。
[^q1]: 质疑 · 某研究。证据强度：中。
[^v1]: 原片 00:20。
```

预期结果：

```text
脚标校验：错误示例.md
[错误] 3 条
  [E002] 第 20 行：编号 [^v1] 重复定义（首次定义在第 17 行）
  [E001] 第 7 行：引用 [^v7] 没有对应的定义 [^v7]:
  [E005] frontmatter evidence_support=2，实际 s 类型定义为 1 条
[警告] 1 条
  [W001] 第 19 行：定义 [^q1]: 未被正文引用
[统计] 中文字符 43｜脚标引用 3 个（唯一定义 3 个）｜密度 未校验（中文字符不足 100）
[统计] 定义：v 1｜s 1｜q 1｜d 0｜u 0
[结果] FAIL（存在 error）
```

这个例子同时命中：引用无定义（`E001`）、重复定义（`E002`）、
frontmatter 自报数量不符（`E005`）、定义未使用（`W001`）。
因为中文字符不足 100，密度规则不参与判定。
