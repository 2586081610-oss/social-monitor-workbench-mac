# 内容类型判定与路由（v3）

> 适用：拿到一条作品的 features 后，判定它属于哪种「内容形态」，据此选择笔记模板、读帧预算和输出结构。
> 可执行实现：`tools/classify_content.py`（纯标准库，无第三方依赖）。本文档的公式与阈值必须与该脚本一致，改一处必须同步另一处。
>
> 与现有模板的关系：v3 的四套模板（`01-口播理论类`、`02-动作教学类`、`03-跟练类`、`04-图文收藏类`）是「目的地」；本文档加的是「怎么自动选目的地」。模板正文不变，判定结果只决定选哪一套、读多少帧。

## 一、六个标签

| 标签 | 中文名 | 定义 | 典型特征 |
|---|---|---|---|
| `talking_head` | 口播/理论 | 以人对着镜头或白板讲解为主，重点是观点、机制、经验 | 机位稳定、切镜少、几乎无连续运动、理论词密度高 |
| `workout_demo` | 动作教学/锻炼 | 讲解并示范某个或某组动作，重点是动作要领、错误、变式 | 示范段与讲解段交替、有单次动作尖峰、动作词密度高 |
| `follow_along` | 跟练/带练 | 完整训练课，观众跟着做，重点是顺序、组数、次数、休息 | 长时间连续运动、组数/次数口令密集、几乎不切镜 |
| `collection_post` | 图文/收藏 | 没有视频，或视频只是图片轮播；重点是条目清单与归并 | 无视频、图片多、时长接近 0 |
| `vlog` | 生活记录/对话剧情 | 生活流水、探店、旅拍、对话或剧情，重点是时间线与人/事 | 场景切变率高、对话轮次多、无训练结构 |
| `unknown` | 置信不足 | 信号不足或两类打平，不硬判 | 分数低、领先幅度小、关键字段缺失 |

标签命名固定为蛇形小写，写入笔记 front matter 或流水线字段时不要翻译、不要加空格。

## 二、这是「内容形态」，不是「兴趣类目」

`monitor/triage.py` 判的是**兴趣类目**：`ai_tools`、`fitness`、`money`、`travel`、`drama` 等，回答「这条值不值得做笔记、进不进知识库」。

本文档判的是**内容形态**：`talking_head`、`workout_demo`、`follow_along` 等，回答「做笔记时用哪套模板、读多少帧」。

两者正交，必须分开存：

| 维度 | 回答的问题 | 取值来源 | 存哪 |
|---|---|---|---|
| 兴趣类目 | 要不要做、优先级多高 | `triage.py` 的 `category` | 分诊结果 / 队列 |
| 内容形态 | 怎么做、用什么模板 | 本文档的 `kind` | 笔记元数据 / 出稿任务 |

组合示例：

- `fitness` + `follow_along` → 健身跟练，走 `03-跟练类`，组数与动作顺序全部挂原片脚标。
- `fitness` + `talking_head` → 健身理论，走 `01-口播理论类`，机制与剂量必须做外部核对。
- `fitness` + `workout_demo` → 单个动作教学，走 `02-动作教学类`。
- `ai_tools` + `talking_head` → 工具讲解，仍走 `01`，但「外部对照」换成官方文档与版本信息。
- `drama` + `vlog` → 剧情娱乐通常 `archive`，不做笔记；若人工要求做，走 vlog 轻量结构。

不要用形态标签覆盖类目标签，也不要用 `fitness` 去推形态：健身视频既可能是口播，也可能是跟练。

## 三、信号表

所有比例类字段取值 0~1；密度类字段为「每分钟次数」。

| 信号 | 字段 | 单位 | 主要区分 | 说明与取数 |
|---|---|---|---|---|
| 时长 | `duration_seconds` | 秒 | 跟练 vs 动作教学、短视频 | 视频容器时长；与 `frames.py` 的 `video_duration_seconds` 同源 |
| 口播密度 | `speech_ratio` | 0~1 | 弱信号 | 有语音覆盖的时长 / 总时长；ASR 段的时间并集 |
| 静音比例 | `silence_ratio` | 0~1 | 弱信号 | 无语音时长占比；缺省按 `1 - speech_ratio` 推导 |
| 场景切变率 | `scene_cut_per_min` | 次/分 | vlog vs 教学/跟练 | `scan_scene_cuts` 的切变点数 / 分钟 |
| 连续运动覆盖率 | `continuous_motion_ratio` | 0~1 | 口播 vs 动作 vs 跟练 | 逐秒画面差分超过阈值、且连续成段的时间占比 |
| 运动尖峰比例 | `motion_spike_ratio` | 0~1 | 动作教学 vs 口播 | 画面差分出现短促高峰的时长占比（单次动作、起落杠） |
| 组数/次数密度 | `set_rep_density` | 次/分 | 跟练 vs 动作教学 | 转写中「组、次、个、秒、休息」等计次表述的出现频次 |
| 跟练词命中 | `keyword_hits.follow_along` | 次 | 跟练 | 「跟我做、准备、开始、下一个、休息、再来一组」等 |
| 动作词命中 | `keyword_hits.action` | 次 | 动作教学 | 动作名、器械名、身体部位、握法、幅度等 |
| 理论词命中 | `keyword_hits.theory` | 次 | 口播/理论 | 「原理、因为、机制、研究、意思是、本质」等 |
| 对话轮次密度（辅助，可选） | `dialogue_turn_per_min` | 轮/分 | vlog | 说话人切换或问答式转写的轮次；无说话人分离时可留空 |
| 口播字速（辅助，可选） | `chars_per_minute` | 字/分 | 口播/理论 | 转写字数 / 分钟；用于区分「真讲解」与「短口令」 |
| 图片数 | `image_count` | 张 | 图文/收藏 | 图文作品的图片数量；纯视频填 0 |
| 是否有视频 | `has_video` | 布尔 | 图文/收藏 | 缺省按 `true` |
| 是否有转写 | `has_transcript` | 布尔 | 置信度 | ASR 失败或纯图文填 `false`；缺省按 `true` |

**取数注意**

1. `scene_cut_per_min`、`continuous_motion_ratio`、`motion_spike_ratio` 需要全片扫描，与 `frames.py` 的 `scan_scene_cuts` / `scan_frame_quality` 同一次扫描即可，不要为分类单独再跑一遍 ffmpeg。
2. 关键词命中按「去重词条命中次数」计，同一句重复喊同一口令不重复计数，避免跟练视频把跟练词刷到虚高。
3. `speech_ratio` 与 `silence_ratio` 应互为补数；两者都给且矛盾时，判定采用二者均值（`voice`），并在 evidence 里留痕。

## 四、打分公式

### 4.1 辅助函数

```text
clamp01(x) = min(1, max(0, x))
ramp(x, lo, hi) = clamp01((x - lo) / (hi - lo))        # x<=lo 取 0，x>=hi 取 1
band(x, a, b, c, d):                                    # 梯形：两端衰减，中间为 1
    x <= a 或 x >= d → 0
    a < x < b        → ramp(x, a, b)
    b <= x <= c      → 1
    c < x < d        → 1 - ramp(x, c, d)
```

### 4.2 变量

```text
Tm   = max(duration_seconds, 60) / 60                   # 分钟，防止短视频除零
voice = (speech_ratio + (1 - silence_ratio)) / 2         # 口播占比
cut   = scene_cut_per_min
motion= continuous_motion_ratio
spike = motion_spike_ratio
setrep= set_rep_density
chars = chars_per_minute
dialogue = dialogue_turn_per_min
follow_rate = keyword_hits.follow_along / Tm
action_rate = keyword_hits.action / Tm
theory_rate = keyword_hits.theory / Tm
```

### 4.3 五类得分（各自权重上限为 100，已是 0~100 分）

```text
talking_head =
    26 * ramp(voice, 0.40, 0.78)
  + 18 * (1 - ramp(motion, 0.20, 0.55))
  + 22 * ramp(theory_rate, 0.15, 0.90)
  + 12 * (1 - ramp(cut, 1.5, 6.0))
  +  8 * (1 - ramp(spike, 0.05, 0.30))
  +  6 * (1 - ramp(setrep, 0.5, 2.5))
  +  8 * ramp(chars, 120, 280)

workout_demo =
    24 * band(motion, 0.18, 0.30, 0.55, 0.82)   # 中等连续运动：示范与讲解交替
  + 18 * ramp(spike, 0.05, 0.30)
  + 24 * ramp(action_rate, 0.40, 2.00)
  + 12 * ramp(setrep, 0.30, 1.50)
  + 12 * (1 - ramp(cut, 3.0, 9.0))
  + 10 * ramp(speech_ratio, 0.15, 0.60)

follow_along =
    34 * ramp(motion, 0.50, 0.85)               # 最强信号
  + 12 * ramp(spike, 0.10, 0.35)
  + 12 * ramp(Tm, 6, 20)
  + 14 * ramp(setrep, 1.0, 3.5)
  + 22 * ramp(follow_rate, 0.12, 0.80)
  +  6 * (1 - ramp(cut, 0.8, 3.0))
  若 0 < duration_seconds < 45：整体 × 0.5（短片惩罚）

collection_post =
    60 * (1 if not has_video else 0)
  + 30 * ramp(image_count, 0, 9)
  + 10 * (1 - ramp(duration_seconds, 30, 180))

vlog =
  g = max(ramp(cut, 2.0, 8.0), ramp(dialogue, 1.0, 4.0))   # 门控
    34 * ramp(cut, 3.0, 12.0)
  + 30 * ramp(dialogue, 1.5, 6.0)
  + 12 * g * (1 - ramp(motion, 0.15, 0.55))
  + 12 * g * (1 - ramp(setrep, 0.2, 1.2))
  + 12 * g * (1 - ramp(follow_rate, 0.05, 0.50))
```

三条硬性限制：

1. `has_video = false` 时，`talking_head`、`workout_demo`、`follow_along`、`vlog` 一律置 0，只保留 `collection_post`。
2. `vlog` 的后三项必须乘门控 `g`。不乘门控会出现「什么都不像」被判成 vlog 的假阳性。
3. 权重是对称设计的：每类满分 100，不做跨类归一，方便直接比较与写阈值。

### 4.4 判定阈值

| 条件 | 结果 | 置信度 | needs_llm |
|---|---|---|---|
| 最高分 < 45 | `unknown` | low | true |
| 最高分 ≥ 45 且领先 ≥ 12 | 采纳最高分 | 最高分 ≥ 70 → high，否则 medium | false |
| 最高分 ≥ 45 且 6 ≤ 领先 < 12 | 采纳最高分 | medium | true |
| 领先 < 6 且最高分 ≥ 60 | 采纳最高分 | low | true |
| 领先 < 6 且最高分 < 60 | `unknown` | low | true |

补充封顶规则（在上述结果之后执行）：

| 情况 | 处理 |
|---|---|
| 无视频且有图片 | 直接判 `collection_post`；图片 ≥ 6 张为 high，否则 medium |
| 无视频且无图片 | `unknown` + low + needs_llm |
| 缺 `continuous_motion_ratio` | 置信度封顶 medium，needs_llm = true |
| `has_video=true` 且 `has_transcript=false` | 置信度封顶 medium，needs_llm = true |
| `has_video=true` 且时长 ≤ 0 | needs_llm = true |
| `0 < 时长 < 20 秒` | needs_llm = true |

### 4.5 为什么不能单看口播密度

口播密度（`speech_ratio`）在三类里都很高：口播理论全程说话，动作教学边做边讲，跟练全程喊口令。它只能把「图文/收藏」和「有视频内容」分开，无法区分前三类。

- 在 `talking_head` 里，`voice` 的权重是 26，只占四分之一；单独拉满也只能把总分推到 26 左右，不足以越过 45 分门槛。
- `workout_demo` 里口播只占 10 分，`follow_along` 则完全不看口播（只统计跟练口令词），都属于加分项而不是判别项。

真正的判别信号是**运动波形**：

- `continuous_motion_ratio`：口播通常 < 0.20，动作教学 0.30~0.55，跟练 > 0.60。
- `motion_spike_ratio`：动作教学有短促尖峰但不成片，跟练是持续的高尖峰比例。
- 因此 `follow_along` 给连续运动 34 分（最高单项），`workout_demo` 用梯形函数奖励「中等覆盖」，超过 0.82 反而减分——这正是「跟练」与「讲解式示范」的分界。

## 五、路由表

| content_kind | 模板文件 | 建议读帧预算 | 建议输出结构 |
|---|---|---|---|
| `talking_head` | `docs/note-templates/v3/01-口播理论类.md` | 每 40 秒一帧，6~24 帧 | 一句话结论 / 概念定义 / 机制链 / 分节要点 / 反例与边界条件 / 外部对照 / 证据台账 |
| `workout_demo` | `docs/note-templates/v3/02-动作教学类.md` | 每 18 秒一帧，8~40 帧 | 一句话结论 / 动作定位 / 握法·站位·关节角度表 / 动作分解表 / 口令清单 / 常见错误 / 变式与退阶 / 证据台账 |
| `follow_along` | `docs/note-templates/v3/03-跟练类.md` | 每 30 秒一帧，8~32 帧 | 一句话结论 / 训练参数表 / 分节要点 / 画面实读 / 纠错 / 外部对照 / 证据台账 |
| `collection_post` | `docs/note-templates/v3/04-图文收藏类.md` | 等于图片数（0 图则 0 帧） | 条目清单 / 主题归并 / 去重与边界 / 来源可信度分级 / 外部核查 / 证据台账 |
| `vlog` | `docs/note-templates/v3/05-vlog类.md` | 每 45 秒一帧，4~16 帧 | 一句话结论 / 时间线（按场景）/ 关键信息与人·物 / 可复用信息 / 待确认 |
| `unknown` | 无 | 0 帧 | 不路由；先补 features 或交 LLM/人工复核 |

说明：

1. 这里的帧预算是**建议值**，最终仍受 `frames.py` 的 `frame_budget`（默认每 25 秒一帧、6~60 帧）与 `max_total_frames=90` 硬上限约束，取二者较小值。
2. `workout_demo` 帧预算最密，因为姿势判定依赖关键位（起始、离心、底部、错误示范）；`follow_along` 只需核对热身/主项/收尾/错误位，帧不必多；`vlog` 只取场景代表帧。
3. `vlog` 使用 `05-vlog类.md`，只写时间线、关键信息与可复用信息；没有可核验主张时，「外部对照」写「无」，不要硬凑文献。
4. `unknown` 不产出笔记。
5. 表中的输出结构只列核心章节；`〇、来源与素材摘要`、`待确认`、`质量自评` 等固定章节以模板文件为准，不要因路由结果删减。

## 六、输入 schema（features）

```json
{
  "duration_seconds": 720,
  "speech_ratio": 0.82,
  "silence_ratio": 0.15,
  "scene_cut_per_min": 0.8,
  "continuous_motion_ratio": 0.08,
  "motion_spike_ratio": 0.02,
  "set_rep_density": 0.1,
  "chars_per_minute": 260,
  "dialogue_turn_per_min": 0.2,
  "keyword_hits": {
    "follow_along": 0,
    "action": 1,
    "theory": 9
  },
  "has_video": true,
  "has_transcript": true,
  "image_count": 0
}
```

| 字段 | 类型 | 必填 | 缺失时默认 | 说明 |
|---|---|---|---|---|
| `duration_seconds` | number | 是 | 0.0，并入 `missing_fields` | 秒；≤0 视为未知 |
| `speech_ratio` | number | 是 | 0.0 | 0~1 |
| `silence_ratio` | number | 否 | `1 - speech_ratio` | 0~1 |
| `scene_cut_per_min` | number | 是 | 0.0 | 次/分 |
| `continuous_motion_ratio` | number | 是 | 0.0 | 最强信号，缺失会强制 needs_llm |
| `motion_spike_ratio` | number | 是 | 0.0 | 0~1 |
| `set_rep_density` | number | 否 | 0.0 | 次/分 |
| `chars_per_minute` | number | 否 | 0.0 | 字/分 |
| `dialogue_turn_per_min` | number | 否 | 0.0 | 轮/分 |
| `keyword_hits` | object | 否 | 三个键全为 0 | 缺失按 0 计，并记 `keyword_hits.<key>` |
| `has_video` | boolean | 否 | true | 缺失记入 `missing_fields` |
| `has_transcript` | boolean | 否 | true | 缺失记入 `missing_fields` |
| `image_count` | number | 否 | 0 | 张 |

约定：

1. 非数值、负值、越界值按保守默认处理，不抛异常；缺失字段全部写入输出的 `missing_fields`，供上游补采。
2. 不做单位猜测：`duration_seconds` 只收秒，`*_per_min` 只收每分钟值。
3. 文本类字段（标题、转写）不进 features：关键词与密度应在上游算好，判定器保持纯数值、可离线回归。

## 七、输出 schema

```json
{
  "kind": "talking_head",
  "label": "口播/理论",
  "confidence": "high",
  "scores": {
    "talking_head": 94.6,
    "workout_demo": 22.0,
    "follow_along": 11.1,
    "collection_post": 0.0,
    "vlog": 0.0
  },
  "margin": 72.6,
  "runner_up": "workout_demo",
  "evidence": [
    {"signal": "语音覆盖率", "value": 0.83, "points": 26.0, "text": "语音覆盖约 84%"}
  ],
  "template": "docs/note-templates/v3/01-口播理论类.md",
  "template_note": "",
  "frame_budget": 18,
  "structure": ["一句话结论", "概念定义", "机制链", "分节要点", "反例与边界条件", "外部对照", "证据台账"],
  "needs_llm": false,
  "missing_fields": [],
  "warnings": []
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `kind` | string | 六个标签之一 |
| `label` | string | 中文名 |
| `confidence` | string | `high` / `medium` / `low`，与 `triage.py` 用同一套词 |
| `scores` | object | 五类得分，0~100，保留 1 位小数 |
| `margin` | number | 最高分减第二名 |
| `runner_up` | string | 第二名的 kind |
| `evidence` | array | 胜出 kind 的前 5 条加分项；`unknown` 时给最高分那类的证据，便于排查 |
| `template` | string 或 null | 相对仓库根路径；`unknown` 为 null |
| `template_note` | string | 模板使用备注，可能为空 |
| `frame_budget` | number | 建议帧数；图文等于图片数 |
| `structure` | array | 建议章节顺序 |
| `needs_llm` | boolean | 是否需要 LLM 或人工复核 |
| `missing_fields` | array | 缺失或非法的输入字段名 |
| `warnings` | array | 降级原因说明 |

`evidence` 每项都是「哪个信号、取什么值、加了多少分、怎么解释」，出稿时可直接作为「为什么选这个模板」的说明。

## 八、CLI 用法

```bash
# 人类可读摘要
python3 docs/note-templates/v3/tools/classify_content.py --input features.json

# 管道输入 + JSON 输出
cat features.json | python3 docs/note-templates/v3/tools/classify_content.py --stdin --json

# 内置用例自检（退出码 0 表示全部通过）
python3 docs/note-templates/v3/tools/classify_content.py --self-test
```

工具只读输入、只写 stdout，不联网、不写文件、不读仓库其它文件。

## 九、示例

三个示例与 `--self-test` 内置用例完全一致，下面的输出是脚本实际运行结果。

### 9.1 口播/理论

输入：

```json
{
  "duration_seconds": 720,
  "speech_ratio": 0.82,
  "silence_ratio": 0.15,
  "scene_cut_per_min": 0.8,
  "continuous_motion_ratio": 0.08,
  "motion_spike_ratio": 0.02,
  "set_rep_density": 0.1,
  "chars_per_minute": 260,
  "dialogue_turn_per_min": 0.2,
  "keyword_hits": {"follow_along": 0, "action": 1, "theory": 9},
  "has_video": true,
  "has_transcript": true,
  "image_count": 0

```

## 十、边界情况

| 情况 | 表现 | 处理 |
|---|---|---|
| 无视频、有图片 | `has_video=false`、`image_count>=1` | 直接路由 `collection_post`，帧预算等于图片数；其余四类置 0，避免「无画面」被算成「口播的静止画面」 |
| 无视频、无图片 | `has_video=false`、`image_count=0` | `unknown` + low + needs_llm，提示「无视频且无图片」 |
| 无转写（ASR 失败） | `has_transcript=false` | 关键词三项按 0 计，置信度封顶 medium 且 needs_llm = true；形态仍可由运动信号判出，但组数/次数缺失，必须复核 |
| 时长未知 | `duration_seconds=0` | 关键词密度用 1 分钟兜底，帧预算取该形态下限，needs_llm = true |
| 短视频（< 20 秒） | 有视频但信号不完整 | 允许判形态，但 needs_llm = true；读帧不超过该形态上限，优先人工确认 |
| 短视频（20~45 秒） | 运动可能很密集 | `follow_along` 得分乘 0.5，防止一个 30 秒快剪被当成跟练课 |
| vlog | 切变快、对话多、无训练结构 | 必须由 `scene_cut_per_min` 或 `dialogue_turn_per_min` 正向触发门控；两项都为 0 时 vlog 恒为 0，避免「什么都缺 → vlog」 |
| 动作教学 vs 跟练 | 两者都有动作词、都有运动 | 看连续运动覆盖率与时长：0.30~0.55 且时长 < 6 分钟偏动作教学；> 0.60 且 > 6 分钟、组数密度 > 1 偏跟练。两者分差 < 12 时交 LLM |
| 长视频口播里穿插演示 | 运动信号被抬到 0.3 左右 | 口播的「低运动」项会减分，但仍靠理论词与字速拉回；分差小时不硬判，走 needs_llm |
| 无声跟练（只有字幕/音乐） | 组数密度与跟练词都为 0 | 仍可凭连续运动 + 时长判 `follow_along`；若同时无转写，置信度封顶 medium，需复核 |
| 纯音乐卡点/舞蹈 | 连续运动高、切变高、无组数 | 可能落在 `follow_along` 与 `vlog` 之间；分差 < 12 时 needs_llm，不自动出笔记 |
| 直播回放 | 时长极长、切变低、口播高 | 按公式通常判 `talking_head`；帧预算受 24 帧上限约束，需要时人工上调 |

## 十一、低置信不硬判

规则只有一句：宁可返回 `unknown`，不要猜。

1. 最高分 < 45：不路由，输出 `unknown` + low + needs_llm。
2. 领先 < 6 且最高分 < 60：不路由，输出 `unknown` + low + needs_llm。
3. 领先 < 12：允许路由，但必须 `needs_llm = true`，由 LLM 结合转写与画面复核后再出稿。
4. 最强信号（`continuous_motion_ratio`）缺失：置信度最多 medium，且必须复核。
5. 有视频但无转写：置信度最多 medium，且必须复核（组数/次数无法自动核对）。
6. `unknown` 时 `template` 为 null、`frame_budget` 为 0，下游不得默认套用口播模板。

下游处理约定：

- `needs_llm = false`：直接按 `template` 与 `structure` 出稿。
- `needs_llm = true` 且 `kind != unknown`：先用该模板起草，把 `evidence` 与 `warnings` 一并交给复核，复核只确认形态，不重写模板。
- `kind == unknown`：不进入自动出稿队列，转人工或 LLM 分诊；补采 `missing_fields` 后可重新判定。

## 十二、维护约定

1. 改公式、改阈值、改权重上限，必须同时改 `tools/classify_content.py`，并保证 `--self-test` 通过。
2. 新增形态（如 `podcast`、`interview`）时，需同时补：标签定义、信号表中该形态的判别信号、公式、路由表、至少一个 self-test 用例。
3. 新用例优先从真实误判里取，不要只造「一看就对」的样本。
4. 判定器保持纯函数：不读数据库、不读媒体文件、不联网。features 的采集是上游职责。
